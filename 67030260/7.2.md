## 5. กิจกรรมถอดรหัสซอร์สโค้ดและเขียนผังงาน (Code Deconstruction & Sequence Flow Assignment)

ให้นักศึกษาแกะรอยการทำงานจาก `main/main.c` ในโหมด SoftAP แล้วเขียน **แผนภาพลำดับเหตุการณ์ (Sequence Diagram)**:

### ภารกิจที่ 1: ผังลำดับการสื่อสารผ่าน HTTP Endpoints (SoftAP Scheme Sequence Flow)
ให้นักศึกษาวาด Sequence Diagram แสดงปฏิสัมพันธ์ระหว่าง 3 ฝ่าย:
1. **Smartphone App (ESP SoftAP Prov)**
2. **ESP32 SoftAP Webserver (Protocomm Layer)**
3. **Wi-Fi Router (AP ปลายทาง)**

**จุดที่ต้องระบุในผัง:**
- จังหวะที่มือถือยิง HTTP POST ไปยัง Endpoint แต่ละตัว (`/prov-session`, `/prov-scan`, `/prov-config`)
- Event ของ ESP-IDF ที่ถูก Trigger ใน `event_handler()` เช่น:
  - `WIFI_EVENT_AP_STACONNECTED`
  - `PROTOCOMM_SECURITY_SESSION_SETUP_OK`
  - `WIFI_PROV_CRED_RECV`
  - `WIFI_PROV_CRED_SUCCESS`
  - `IP_EVENT_STA_GOT_IP`
- สถานะจังหวะการกระพริบของ **LED 3 (GPIO 5)** และ **LED 1 (GPIO 2)** ในแต่ละช่วง

```text
sequenceDiagram
    autonumber
    actor User as Smartphone App<br/>(ESP SoftAP Prov)
    participant ESP as ESP32 SoftAP<br/>(Protocomm Server)
    participant Router as Wi-Fi Router<br/>(Target AP)

    Note over ESP: เริ่มต้นระบบ: provisioned == false<br/>LED 3 (GPIO 5) = ON (SoftAP Active)<br/>LED 1 (GPIO 2) = OFF
    
    User->>ESP: เชื่อมต่อ Wi-Fi "PROV_67030260"
    ESP-->>ESP: Trigger Event: WIFI_EVENT_AP_STACONNECTED

    Note over User,ESP: 1. สร้าง Secure Session (Security 1)
    User->>ESP: HTTP POST /prov-session (แลกเปลี่ยน Key + PoP: "abcd1234")
    ESP-->>ESP: Trigger Event: PROTOCOMM_SECURITY_SESSION_SETUP_OK
    ESP-->>User: ตอบกลับ Session Established (200 OK)

    Note over User,ESP: 2. สแกนค้นหาเครือข่าย Wi-Fi
    User->>ESP: HTTP POST /prov-scan (ร้องขอรายการ AP)
    ESP-->>User: ส่งรายการ Wi-Fi SSID กลับไป

    Note over User,ESP: 3. ส่งข้อมูล Wi-Fi Credentials
    User->>ESP: HTTP POST /prov-config (ส่ง Target SSID & Password)
    ESP-->>ESP: Trigger Event: NETWORK_PROV_WIFI_CRED_RECV<br/>(พิมพ์ SSID/Password ออก Serial)
    ESP-->>User: บันทึกข้อมูลและตอบกลับ Status OK

    Note over ESP,Router: 4. ESP32 พยายามเชื่อมต่อไปยัง Router
    ESP->>Router: ส่งคำขอเชื่อมต่อ (Wi-Fi Association & Handshake)
    Router-->>ESP: ยืนยันการเชื่อมต่อสำเร็จ
    ESP-->>ESP: Trigger Event: NETWORK_PROV_WIFI_CRED_SUCCESS<br/>LED 3 (GPIO 5) = OFF (ปิดไฟ SoftAP)
    
    Router-->>ESP: แจกจ่าย DHCP IP Address
    ESP-->>ESP: Trigger Event: IP_EVENT_STA_GOT_IP<br/>LED 1 (GPIO 2) = ON (เชื่อมต่อ Wi-Fi สำเร็จ)
    
    Note over ESP: Trigger Event: NETWORK_PROV_END<br/>เรียก network_prov_mgr_deinit()
```

## 7. คำถามท้ายการทดลอง (Post-Lab Questions)
1. ในโหมด SoftAP Scheme สมาร์ตโฟนส่งข้อมูลหา ESP32 ผ่านโปรโตคอลและ IP Address ใด?
> โปรโตคอล: ใช้งาน HTTP (ผ่าน Transport Layer TCP Port 80) โดยส่งข้อมูลผ่านรูปแบบ Protobuf (Protocol Buffers) ผ่าน HTTP POST Endpoints (เช่น /prov-session, /prov-scan, /prov-config) ภายใต้เลเยอร์ความปลอดภัย Protocomm Security IP Address: สมาร์ตโฟนจะส่งข้อมูลไปยัง ESP32 ที่หมายเลข 192.168.4.1 (ซึ่งเป็น Default Gateway และ Default IP ของ ESP32 SoftAP Interface)
2. หากผู้ใช้ป้อนรหัสผ่าน Wi-Fi ผิดในแอปมือถือ จะเกิด Event ใดขึ้นบน ESP32 (`WIFI_PROV_CRED_FAIL` หรือไม่) และ ESP32 มีพฤติกรรมอย่างไร?
> Event ที่เกิดขึ้น: เกิด Event NETWORK_PROV_WIFI_CRED_FAIL (หรือ WIFI_PROV_CRED_FAIL ใน SDK เดิม) พฤติกรรมของ ESP32:เมื่อ ESP32 พยายามใช้รหัสผ่านที่ได้รับไปเชื่อมต่อกับ Router แล้วล้มเหลว ระบบจะตัดการเชื่อมต่อไปยัง Router และส่งสถานะแจ้งเตือนข้อผิดพลาด (Authentication Fail / Connection Failed) กลับไปยังแอปมือถือผ่านทาง SoftAP HTTP Session ESP32 จะ ไม่ปิด SoftAP Mode แต่จะยังคงเปิดเครือข่าย Wi-Fi SoftAP และเปิด Webserver ทิ้งไว้ พร้อมคงสถานะไฟ LED 3 (GPIO 5) ให้ติดสว่าง เพื่อรอให้ผู้ใช้งานในแอปมือถือกรอกรหัสผ่าน Wi-Fi หรือเลือก SSID ใหม่อีกครั้ง
3. ทำไมผู้ผลิต IoT ส่วนใหญ่จึงมองว่ากระบวนการเชื่อมต่อแบบ SoftAP มีขั้นตอนที่ยุ่งยากสำหรับผู้ใช้ทั่วไปเมื่อเทียบกับ BLE?
> ต้องสลับสัญญาณ Wi-Fi ด้วยตนเอง (Manual Wi-Fi Switching): โทรศัพท์มือถือต้องตัดขาดจากอินเทอร์เน็ตบ้านหรือเน็ตมือถือชั่วคราว เพื่อไปค้นหาและกดเชื่อมต่อกับ Access Point ของ ESP32 (เช่น PROV_67030260) ก่อน จึงจะเริ่มตั้งค่าได้ ระบบความปลอดภัยของ OS มือถือ (Captive Portal / No Internet Prompts): ทั้ง iOS และ Android มักจะเด้งเตือนว่า "Wi-Fi นี้ไม่มีการเชื่อมต่ออินเทอร์เน็ต" และอาจตัดกลับไปใช้ 4G/5G หรือ Wi-Fi เดิมอัตโนมัติ ทำให้กระบวนการหลุดกลางคัน ประสบการณ์การใช้งาน (UX) ด้อยกว่า: โหมด BLE สามารถสแกนและจับคู่ได้ทันทีภายในแอปพลิเคชันโดยที่มือถือยังคงต่อเน็ตบ้านได้ตามปกติ ไม่ต้องสลับหน้าจอไปที่ Settings ของมือถือเพื่อต่อ Wi-Fi หลายขั้นตอนเหมือน SoftAP
